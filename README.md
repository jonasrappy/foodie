# Foodie

Foodie is a shared shopping list and meal planner for a household tablet. Keep groceries on one side and requests for next week's meals on the other. Changes sync between devices as you make them.

The web app runs on a Go server with SQLite. An optional Android app adds hands-free voice control, screen wake and a small animated 3D character. The Android app loads the web interface, so changes to the interface do not require another APK.

English is the default. Danish is included.

## What it does

- Shopping items with quantities, units and purchased checkboxes.
- A separate list of requested meals for next week.
- Live updates, saved drafts and an offline queue that retries without duplicating items.
- A household password remembered on each device until the password changes.
- A bot API that separates items to buy from items already purchased.
- Optional Android voice control: say “Hey Foodie”, add an item, then continue or say “no thanks”.
- Duplicate detection with confirmation before increasing a quantity.
- A voice character that speaks, listens, blinks and moves throughout the conversation.

## Run it locally

Install Go 1.27.1 or newer and Make. Node.js is only needed when rebuilding the 3D asset or running browser tests.

```sh
git clone https://github.com/jonasrappy/foodie.git
cd foodie
make build
./bin/foodie init
./bin/foodie serve
```

Open `http://127.0.0.1:8082`.

`foodie init` creates `.env` with file mode `0600`. It generates a separate random household password, password salt, session secret and bot token. Open that file locally to get the password. The command will not overwrite an existing file or print its secrets.

`.env.example` lists the settings without usable credentials. You do not need to copy it before running `init`.

The server binds to loopback. Put nginx or another HTTPS reverse proxy in front of it for access from a tablet or another computer.

## Configuration

Foodie reads `.env` in the working directory. Set `FOODIE_ENV_FILE` or pass `--config /path/to/file.env` to use another file. Process environment variables override file values. Explicit `--listen`, `--data-dir` and `--public-dir` flags override both.

Values are literal. Quoted values are supported, but shell commands and variable references are never expanded. Do not source `.env` as a shell script.

| Setting | Purpose | Default |
| --- | --- | --- |
| `FOODIE_LANGUAGE` | Interface, API replies and Android voice language | `en` |
| `FOODIE_TIMEZONE` | Timezone reported to the bot | `UTC` |
| `FOODIE_LISTEN` | Loopback HTTP address | `127.0.0.1:8082` |
| `FOODIE_DATA_DIR` | Database and backup directory | `./data` |
| `FOODIE_PUBLIC_DIR` | Web assets | `./public` |
| `FOODIE_SITE_URL` | Your HTTPS origin, used when building Android | Must be set for Android |
| `FOODIE_PASSWORD` | Household login password | Generated by `init` |
| `FOODIE_PASSWORD_SALT` | Stable salt for password hashing | Generated by `init` |
| `FOODIE_SESSION_SECRET` | Signs device sessions | Generated by `init` |
| `FOODIE_BOT_TOKEN` | Independent, non-expiring bot credential | Generated by `init` |

Existing installations may provide `FOODIE_PASSWORD_HASH` and `FOODIE_BOT_TOKEN_HASH` instead of plaintext values. Do not set both forms of the same credential.

### English and Danish

```dotenv
FOODIE_LANGUAGE=en
FOODIE_TIMEZONE=UTC
```

For Danish:

```dotenv
FOODIE_LANGUAGE=da
FOODIE_TIMEZONE=Europe/Copenhagen
```

Language packs live in `internal/i18n/locales/en.json` and `da.json`. They contain interface text, errors, voice replies and singular/plural unit labels. For example, `1 pack` and `2 packs` become `1 pakke` and `2 pakker` in Danish.

Restart the server after changing its settings. The web interface picks up the new language. Android's native text, speech-recognition locale and TTS voice are selected from the same setting when the APK is built, so rebuild the APK when changing its voice language.

English voice examples:

```text
Hey Foodie
Two packs of grapes
Yes, one bag of apples
No thanks
```

Danish voice examples:

```text
Hey Foodie
To pakker vindruer
Ja, en pose æbler
Nej tak
```

## HTTPS deployment

The `deploy` directory contains nginx and systemd examples. Replace the reserved example hostname with your own domain. The examples use `/opt/foodie` for the application and `/var/lib/foodie` for data.

1. Build the Go executable and copy the application to your chosen directory.
2. Create an unprivileged `foodie` service user.
3. Generate a private environment file, or securely copy your existing settings to `/etc/foodie/foodie.env`.
4. Give the service user read access to that file and write access to the data directory.
5. Configure nginx, obtain a certificate with Let's Encrypt, and enable `foodie.service`.
6. Enable `foodie-backup.timer` if you want daily backups.

The server sets `X-Robots-Tag`, the HTML includes no-index directives, and `robots.txt` disallows crawling. Authentication protects the lists. Keep `.env`, databases, backups and signing keys outside any public static-file directory.

The download endpoint checks authentication before serving an APK. Do not configure nginx to serve the downloads directory directly.

## Android app

The Android app uses Java and Android's WebView. It supports Android 6 and newer, targets Android 15, and includes ARM64 and ARMv7 voice libraries. A recent Android System WebView is required. Landscape tablets are the main use case; the browser interface also adapts to phones and desktop screens.

Build requirements:

- JDK 21.
- Android SDK platform `android-35` and build tools `35.0.0`.
- Python 3, OpenSSL and `zip`.

Set these values in your private `.env`:

```dotenv
FOODIE_SITE_URL=https://your-own-host.example
FOODIE_LANGUAGE=en
ANDROID_SDK_ROOT=/path/to/android-sdk
ANDROID_APPLICATION_ID=app.foodie.mobile
ANDROID_SIGN_DIR=./.private/android-signing
ANDROID_KEY_ALIAS=foodie
ANDROID_VERSION_NAME=1.3.1
ANDROID_VERSION_CODE=7
```

Use your real HTTPS hostname. Foodie currently expects to be hosted at the origin root, not a subdirectory.

```sh
./android/build.sh
```

The first build downloads the pinned voice model and native libraries, then checks every file against `android/vendor-checksums.json`. The large downloaded files stay out of Git. Required Java bindings and license notices are included in the repository.

The build creates `android/build/foodie.apk`. If no signing key exists, it creates one in `ANDROID_SIGN_DIR`. Back up that directory securely. Keep the application ID, key alias and signing key when updating an existing installation. Increase `ANDROID_VERSION_CODE` for each distributed update.

To also make the APK available through the authenticated web download link:

```sh
FOODIE_PUBLISH_APK=1 ./android/build.sh
```

The APK is stored at `downloads/foodie.apk`. Browsers download it using a short-lived signed link. No household password or bot token is compiled into the APK. Your configured server URL is necessarily present in your own build; APK files are excluded from Git.

### Voice and screen wake

Open the Android app, log in, tap the microphone and enable voice control. Allow microphone access. For background screen wake, also allow “Display over other apps” and follow the battery-settings prompt.

The wake word is detected locally. Android's speech service recognizes the following command and may send that short recording to its provider. Foodie's server receives the text, not microphone audio.

Foodie asks what to add, confirms the addition and asks “Anything else?”. A negative reply ends the conversation. Five seconds without starting a reply closes it silently. If an item is already present, Foodie asks before increasing its quantity.

Screen wake depends on Android permissions and device power management. Foodie can appear over the lock screen when enabled, but it does not unlock the device. Test this behaviour on your own tablet. Voice control must be enabled from the visible app; it does not start a microphone service automatically after a reboot.

## Bot API

Give your bot `FOODIE_BOT_TOKEN` through its own secret storage. The token does not expire. Send it as a Bearer authorization header, never as a URL parameter.

Read the lists:

```sh
curl "$FOODIE_SITE_URL/api/v1/requirements" \
  -H "Authorization: Bearer $FOODIE_BOT_TOKEN"
```

The response contains:

| Field | Meaning |
| --- | --- |
| `required_meals` | Meals that must be included in the next plan |
| `required_shopping_items` | Unchecked groceries that must be purchased |
| `already_purchased_items` | Checked groceries that must not be purchased again |
| `shopping_items` | Structured rows with text, quantity, unit and checked status |
| `revision` | Version used to protect a later reset |
| `timezone` | Your configured IANA timezone |
| `instructions` | Planning instructions in the configured language |

The bot plans the remaining meals and ingredients itself. It must also avoid purchasing checked items when those items occur in a recipe.

After a successful order, clear both lists using the revision from the response you planned against:

```sh
curl -X POST "$FOODIE_SITE_URL/api/v1/reset" \
  -H "Authorization: Bearer $FOODIE_BOT_TOKEN" \
  -H 'Content-Type: application/json' \
  --data '{"revision":42}'
```

Use the actual revision, not the example number. A `409` response means someone changed a list. Fetch it again and handle the changes before resetting. Reset archives the previous lists in SQLite.

Bot credentials can read requirements and reset lists. They cannot log in as a household device or download the APK.

Units retain stable storage/API identifiers so changing the display language does not change existing data. Readable requirement strings and displayed quantities use the selected language.

| Identifier | English | Danish |
| --- | --- | --- |
| `stk.` | piece / pieces | stk. |
| `liter` | liter / liters | liter |
| `milliliter` | milliliter / milliliters | milliliter |
| `kilo` | kilo / kilos | kilo |
| `gram` | gram / grams | gram |
| `pakker` | pack / packs | pakke / pakker |
| `poser` | bag / bags | pose / poser |
| `dåser` | can / cans | dåse / dåser |
| `flasker` | bottle / bottles | flaske / flasker |
| `bundter` | bunch / bunches | bundt / bundter |
| `bakker` | tray / trays | bakke / bakker |
| `kasser` | crate / crates | kasse / kasser |

## Passwords, backups and updates

To change the household password, send the new password to the command's standard input and restart the server:

```sh
./bin/foodie change-password < /path/to/private-password-file
```

Remove that temporary password file afterwards. The command updates the password hash atomically. Existing device sessions become invalid after restart; the bot credential is preserved. If credentials are supplied through process environment variables, update your environment provider instead.

Create a consistent SQLite backup:

```sh
./bin/foodie backup --output /path/to/backup.sqlite
```

The database filename is `mad.sqlite` for compatibility with earlier installations. Without `--output`, backups go under the data directory and the latest 14 daily backups are retained.

Before updating an existing installation, back up its database, private configuration and Android signing key. Existing JSON credential files remain supported through `--config`. Preserve the original salt, password hash, session secret and bot-token hash when moving them to environment settings. Keep the same data directory to retain lists, revisions and pending voice confirmations.

## Development and tests

```sh
make test check build
```

This runs Go tests with the race detector, static checks and dependency verification. Tests use temporary databases and synthetic credentials. The credentials under `internal/auth/testdata` are compatibility fixtures, not application defaults.

Rebuild the 3D web asset:

```sh
npm ci --prefix frontend --ignore-scripts
npm run --prefix frontend build
```

The bundled web asset is included so normal server setup does not need Node.js. Its source is `frontend/foodie-avatar.js`. Rendering pauses when the conversation is closed or the page is hidden. Reduced-motion settings use static poses.

Browser and native test commands are documented in `test/README.md` and `android/test/README.md`. Run mutating browser tests against an isolated instance, never against household data.
